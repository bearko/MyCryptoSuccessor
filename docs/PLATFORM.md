# bearko.games の共通基盤へのつなぎ込み

My Crypto Successor（successor.bearko.games）を、bearko.games のポータルと共通基盤（共通ログイン・アチーブメント・総合スコア・RTA・全体チャット・遊んだ人の数）につなぐ。共通基盤の側（bearko/MyCryptoPortfolio）は別のセッションが受け持ち、このリポジトリからは変えない。手順の正本はそのリポジトリの `docs/INTEGRATION.md` 3 章と `sdk/v1.js` の先頭のコメント。

- タイトル ID：**`successor`**　ホスト：**`successor.bearko.games`**
- 共通基盤の API は、登録したタイトルのサブドメインからの通信だけを受け付ける。共通基盤の側の登録が本番に出るまでは、SDK の通信は失敗する（ゲームは遊べる。コンソールに通信の失敗が出るだけ）。

## 1. 作り

| 所 | 中身 |
|---|---|
| `index.html` | `<head>` の中、ゲームの本体（Vite が `<head>` に入れる module）より前に `<script defer src="https://bearko.games/sdk/v1.js">` |
| `src/island/platform.ts` | 窓口。ほかのファイルは `window.BearkoGames` を触らず、ここの関数だけを呼ぶ。SDK の型は最小限を自前で書く（npm の依存は足さない） |
| `src/island/p1/main.ts` | つなぐ（`startPlatform`）・チュートリアルの段（`tutReport`）・設定の「全体チャットを開く」・チャットを開いているあいだ時間を止める・通知の場所（`placeToast`） |
| `src/island/p1/trophyui.ts` | 手元に貯めたアチーブメント（`p1/trophy.ts`）を共通基盤へ送る（`syncTrophies`） |
| `tests/platform.test.ts` | SDK が無い・壊れていても例外を出さない／つながる前の段をあとで送る／段の番号と id の決まり／アチーブメントの送り直し |

守ること：

- **SDK が読めない（オフライン・ブロック）・通信に失敗しても、ゲームは最後まで遊べる。** どの呼び出しも try/catch で包み、失敗は `console.warn` だけ。SDK は defer なので、まだ無ければページの `load` を待ってから `init` する。
- ゲーム側は Cookie を触らない（ログイン状態は共通基盤が持つ）。
- `init({ presence: false })` にしない（来訪が止まり、KPI の NUU・DAU・WAU・MAU・RR が数えられなくなる。来訪は SDK が最初の操作で送るので、ゲーム側の作業は無い）。
- 外部の解析タグや自前のプレイログは入れない（数は共通基盤の管理画面で見る）。どうしても足すときは、`await BearkoGames.init(...)` のあと `BearkoGames.isTester()` が true の端末では送らない。
- オフライン：サービスワーカー（`scripts/sw-template.js`）はほかのオリジンへの通信に手を出さないので、SDK は保存しない（オフラインでは読めず、ゲームだけ動く）。

## 2. チュートリアルの段（SDK 1.12.0 の `tutorialStep(step, id)`）

1 か月目のチュートリアル（`p1/tut.ts` の `TUT`）の段に着いたときに送る。表は `src/island/platform.ts` の `TUT_STEPS`（テストが番号と id を見張る）。

| 番号 | id | いつ送るか |
|---|---|---|
| 0 | `start` | 新しいゲームを始めた（最初の段・工房をまだ建てていない・月の報告がまだ）。設定の「最初から」でやり直したセーブも同じ扱い（同じページの中では送り直さない） |
| 3 | `intro_done` | 最初の会話（新天地の 4 枚）を閉じた（「建てる場所を選ぶ」）。始めて十数秒の離脱を見る |
| 10 | `ws_wait` | 工房を建てた（工事の完成を待つ段に着いた） |
| 15 | `craft` | 工房が完成した（作るものを決める段） |
| 20 | `mats` | 作るものを決めた（素材の段） |
| 25 | `shop` | 素材を手配した（お店を建てる段） |
| 30 | `shop_wait` | お店を建てた（完成を待つ段） |
| 35 | `sell` | お店が完成した（並べて売る段） |
| 40 | `haul` | 並べた（運ぶ段） |
| 45 | `first_sale` | 運んだ（初売上の段） |
| 50 | `scm` | 初売上（ダッシュボードの段） |
| 55 | `recruit` | ダッシュボードを見た（人材の募集の段） |
| 60 | `hire` | 募集した（雇ったヒーローを持ち場に付ける段） |
| 65 | `month` | 持ち場に付けた（1 か月目を締める段） |
| 75 | `ranking` | 1 か月目を締めた（企業ランキングを見る段） |
| 90 | `done` | チュートリアルを終えた（最後の会話に入った）。設定の「チュートリアルを終える」で飛ばしたときも |

- 段に「着いた」ときに送る（`TUT[k]` に進んだら、その段の id）。工房の段（`TUT[0]`）は `start` と同じときなので送らない。
- **手引きつきで最初から始めたセーブだけ送る**：最初の段・工房なし・月の報告なしのセーブを見たときに `flags.pfTut` を立て、立っているセーブだけ送る。チュートリアルの無かったころの古いセーブ・途中まで進んだセーブ・自動プレイ（`scripts/island/sim.ts` は画面を通らない）・単体テストは送らない。
- 同じ段は、ページの中で 1 回（窓口）、サーバーは人ごとに最初の 1 回だけ残す。読み直したときに前の段をもう一度呼んでもよい。
- **公開したあとは、番号と id を変えない**（前後の数が比べられなくなる）。段を足すときは空いている番号に入れる。`p1/tut.ts` の段の並びを変えても（`TUT_VERSION`）、ここの番号は変えない。

## 3. 全体チャット

- **右のドック（PC の 1100px 以上で右に 320px）は使わない：`init({ chat: { layout: 'float', button: false } })`。** 理由：このゲームは地図を画面いっぱいに描き、PC では右の帯（部門のパネルと下の帯のタブ）が右端にある。ドックを使うと、その幅を全部の画面（地図・右の帯・まとめた画面・会話）から引く作り直しになる。
- 💬 のボタンも出さない：画面の隅はどこもゲームのキーがある（右下は「次の月へ」の懐中時計、左下はマインちゃんの吹き出し）。
- 開くのは **システム → 設定 →「全体チャットを開く」**（SDK が読めたときだけ出る）。PC は右下の窓、せまい画面は下から出るシートになる（SDK が決める）。
- **窓を開いているあいだは時間を止め**、閉じたら元の速さに戻す（`chat.onToggle`。書いているあいだに月が進んで報告が出る、を防ぐ）。
- 通知（アチーブメントなど）は画面の下。せまい画面では下の帯の上に出す（`toastPlace`：下の帯の高さを見て、画面の大きさが変わったら合わせ直す）。PC では下の帯が右にあるので、下の真ん中（地図の上）。
- 導入の黒い画面は無いので、`chat.setVisible(false)` は使っていない（ボタンを出さないので、隠すものが無い）。

## 4. アチーブメント（`successor.<名前>`）

ゲームの中にはもともとアチーブメント（`p1/trophy.ts`。設定の画面の一覧・取ったときの帯）があり、取ったものは手元（`localStorage` の `successor.trophies`）に「まだ送っていない」として貯めてある。**つながったときと新しく取ったときに、まだ送っていないものを `unlockTrophy('successor.<id>')` で送り、受け付けられたものだけ「送った」にする。** 共通基盤に定義が無いあいだは受け付けられず（400）、次に開いたときに送り直す。定義が出たら、それまでに取ったものもまとめて登録される（未ログインなら仮アカウントに付き、ログインでまとまる）。

条件の案（名前と絵は共通基盤の側で MCH のスキル名から決める）：

| id | 条件 | ゲームの中 |
|---|---|---|
| `first_clear` | はじめて町を制覇する（2 か月続けてエリア 1 位＋研究成果の発表） | **ある**（取ると送る） |
| `first_head` | はじめて事業部長を置き、部門を任せる | **ある** |
| `first_duo` | ヒーローの組み合わせを 1 つ見つける（組み合わせ図鑑） | **ある** |
| `epic_clear` | Epic ランドを制覇する（いまのゲームのクリア） | **ある** |
| `micromanage` | 事業部長を一人も置かずに、すべて自分で指示して Epic ランドを制覇する（やり込み） | **ある** |
| `apprentice` | 1 か月目（見習い期間）を終える | 案（まだ無い） |
| `rank_u` | Uncommon の町へ進出する（1 回目のランクアップ） | 案（まだ無い） |
| `rank_r` | Rare の町へ進出する | 案（まだ無い） |

- 来訪（`successor.visit`）は SDK が送るので作らない。
- 案の 3 つは、共通基盤の定義が決まってから `p1/trophy.ts` に足す（足すとゲームの中の一覧にも出る。絵は `docs/ISLAND_ART_TODO.md`）。
- 共通基盤の通知（「アチーブメント獲得」と登録の案内）は、ゲームの中の帯とは別に出る。重なって煩わしければ、どちらかを止める（あとで決める）。

## 5. 総合スコア（案。口は `submitScore`）

- 種類：**積み上げ（`progress`）**。いまの会社の成績を、月の締めのたびに `{ quiet: true }` で送る。ひと月は標準の速さで 36 秒（⏩ や進行速度でもっと短い）なので、1 分に 1 回までに間引く（間引いたぶんは次に送るときの値に入る）。Epic ランドを制覇した月の締めだけ、通知ありで送る。
- 送る `metrics` の案：

| 名前 | 中身 |
|---|---|
| `conquered` | 制覇した町の数（ランクごと：`{ C, U, R, E }`） |
| `tier` | 進出したいちばん上のランク（C=1・U=2・R=3・E=4・L=5） |
| `cleared` | Epic ランドを制覇したか（いまのゲームのクリア。`epic_clear` と同じ） |
| `months` | 開店からの月の締めの数（クリアまでの月数に使う） |
| `bestSales` | 月の売上の最高（G） |
| `brand` | ブランド力 |
| `regulation` / `difficulty` | `'normal'`（将来の難易度ごとのレギュレーション用。いまは点に効かない） |

- 節目の点：最初の町の制覇 1,000・ゲームクリア（Epic ランドの制覇）5,000。成績 × 係数：制覇した町の数（ランクが上ほど重く）と、月の売上の最高。
- 「ふつうにクリア」の目安（`docs/ISLAND_BALANCE.md` 表 1・表 2。自動プレイ 9 シードの平均）：
  - 通常：8 町を制覇（Common 3・Uncommon 2・Rare 2・Epic 1）、開店から 40.5 か月、実時間 2.4 時間。Epic の町を制覇した月の売上 7.9M G。
  - 100%：20 町を制覇（Epic 3 町まで）、71.8 か月、5.6 時間。Epic の町の月の売上 8.5M〜11.9M G。
  - 最短：3 町（Common 2・Uncommon 1）、0.4 時間。
  - 自動プレイの「通常」は Epic を 1 町で止めているので、Epic ランドの制覇（Epic の町をすべて）は 100% の通しに近い。係数は「通常の 8 町 ≒ 10,000 の手前、Epic ランドの制覇で 10,000 を少し超える」あたりから。
- Legendary の町はまだ無い（できたら、Lime の制覇をクリアにし直し、計算式の版を上げる）。

## 6. RTA（案。口は `rta.start` / `rta.checkpoint` / `rta.abort`）

- レギュレーション案 `successor-lime`：新しいゲームを「RTA で始める」（設定のセーブの画面に置く案）→ 区切り：
  1. `month1`：1 か月目を締める（チュートリアルを終えた月）
  2. `c1`：最初の町を制覇
  3. `rank_u`：Uncommon の町へ進出
  4. `rank_r`：Rare の町へ進出
  5. `rank_e`：Epic の町へ進出
  6. `clear`：Epic ランドを制覇（終わり）
- 短い区間のレギュレーション案 `successor-c1`：始め → `month1` → `c1`（最初の町の制覇まで。自動プレイの最短で 6 分ほど＋チュートリアル）。
- ゲーム内の時間（IGT）：**日数**（`s.day`。速さ（▶・⏩・進行速度）で実時間が変わるので、日数で測る）。`igt: 'days'` として `igtMs` の欄に日数を入れる。実時間は SDK が測る。
- 1 回の挑戦で同じ区切りを何度も送らない（区切りごとにフラグ）。「最初から」でやり直したら `abort`。

## 8. 確かめ方

- 自動：`npx vitest run tests/platform.test.ts`・`npx tsc --noEmit`・`npm run build`（`dist/index.html` で SDK が本体の module より前）・`node scripts/qa/start-bundle.mjs`。
- 手元のブラウザ（作業環境の Playwright。共通基盤の SDK を手元の写しで差し替え、API を偽の返事にする）：
  - SDK あり：チュートリアルを最後まで押して、送った段が `start` → `intro_done` → … → `done` の 16 段そろうこと・来訪（`/api/trophies/visit`）が出ること。
  - SDK なし（`bearko.games` への通信をすべて断つ）：チュートリアルを最後まで通せること（読めない・送れないのはコンソールに出るだけ）。
  - 設定の「全体チャットを開く」で窓が開き、時間が止まり、閉じると元の速さに戻ること。通知がせまい画面で下の帯に重ならないこと。
- 本番：共通基盤の側で `successor` の登録が出たあと、successor.bearko.games を開き、開発者ツールのネットワークで `/api/trophies/visit` と `/api/tutorial/step` が 200 になることを見る。
