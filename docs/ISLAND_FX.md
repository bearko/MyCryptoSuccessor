# アイランド：ドット絵のエフェクト（pixelfx）

プレイヤーへの手応え（フィードバック）の演出を、PixelLab の絵を使わずに **コードで描くドット絵のエフェクト**で足すための決まりです。
ライブラリは [pixelfx](https://github.com/patch-gg/pixelfx)（MIT。Copyright (c) 2026 Patch・Hugo Duprez）。その core と使う効果だけを `src/island/fx/pixelfx/` に写しています（`LICENSE`・`NOTICE.md` を同じ場所に置く）。

段 FX1（2026-11）で、売上のコイン・スキルツリーのパネル・ミッションの受け取り・チュートリアルのクリア・研究成果の発表と制覇の 5 か所に入れて検証しました。結果は下の「検証の結果」。
段 FX2（2026-11）で、棚卸しの「おすすめの順」1〜6（発掘の出土品・昇格・復興とダンジョンの入り口・新しい部門と関所と本社の花火・小さな手応え・製造と撤退と外交）を入れました。結果は「検証の結果（段 FX2）」。

## どこに置くか

| 場所 | 中身 |
| --- | --- |
| `src/island/fx/layer.ts` | 効果を鳴らす層：`playFx(id, x, y, opts)`・`fxAtEl(id, el, opts)`・ゲームの色 `FX_PAL`・計測 `fxStats()`・温め `warmFx()` |
| `src/island/fx/registry.js`・`registry.d.ts` | 使う効果の一覧（id → モジュール）と型。効果を足したら両方に書く |
| `src/island/fx/pixelfx/core/` | pixelfx の core（`fx.js`・`index.js` は character（actor）を外して短くした。ほかはそのまま） |
| `src/island/fx/pixelfx/fx/<分類>/` | 写した効果（ファイルの頭に出どころ。中身はそのまま） |
| `src/island/fx/pixelfx/fx/island/` | ゲームが自分で作った効果（`coin-pop.js`・`hammer-sparks.js`・`rain-band.js`）。pixelfx の作法で書き、pixelfx の道具（render・check）でそのまま描ける |

- JS のまま写す（TypeScript に直さない。直すと元と比べられなくなる）。型は `registry.d.ts` に、使う所だけ書く。
- pixelfx の `act`（キャラクターの動き）・`actor`（効果がキャラクターの体に付く）は写していない。`meta.actor` のある効果（holy/halo・status/burning・ui/level-up など）は、そのままでは使えない。

## 鳴らし方

```ts
import { FX_PAL, fxAtEl, playFx } from '../fx/layer';

// 画面の (x, y)（CSS px）で 1 回。(x, y) は効果の原点（足もと・当たる点）
playFx('firework-burst', x, y, { palette: FX_PAL.ours, opts: { core: FX_PAL.core }, delay: 120 });
// 要素のまんなかで（collect-burst は原点の 30 ドット上で光るので dy: 30）
fxAtEl('collect-burst', button, { palette: FX_PAL.gold, dy: 30 });
// 地図のマスに付ける（カメラが動いても付いていく）
playFx('coin-pop', 0, 0, { layer: 'map', scale: Math.max(1, cam.zoom * 3), anchor: () => ({ x: sx, y: sy }) });
```

| opts | 意味 | 既定 |
| --- | --- | --- |
| `layer` | `'ui'`（いちばん上。お祝い）・`'map'`（地図の上・UI の下。画面やシートを開くと隠れる） | `'ui'` |
| `scale` | 1 ドットを何 CSS px で描くか。デバイスの画素で整数倍になるように丸める | ui：2（スマホ 4/3）・map：1 |
| `palette` | 色のランプ（暗い → 明るい）。下の `FX_PAL` から | 効果の既定 |
| `light` | 光（加算）の強さ | ui 0.7・map 0.4 |
| `ink` | 色のドットの外の 1px のほぼ黒の縁 | true |
| `dy` | 置く位置を上下にずらす（ドットで） | 0 |
| `delay`・`life` | 鳴らすまでの待ち・この時間で薄れて終わる（ms。ループする効果は既定 2000） | 0・最後まで |
| `anchor` | 毎コマの位置を返す（null で隠す） | — |
| `opts` | 効果ごとの設定（firework-burst の `core` など） | — |
| `host`・`under` | 要素の後ろに描く（段 FX2）：`host` の中にキャンバスを入れ、(x, y) は host の左上からの CSS px。`under` を渡すとその要素のすぐ下（並びの順で重ねる。放射の模様の上・文字と絵の下）、無ければ host の中身すべての下（z-index: -1・host は isolation）。host が外されたら消える | — |
| `thin` | 間引きの組（段 FX2）：同じ組は 1 秒（`THIN_MS`）に 1 つまで。続けて来たら出さない（false） | — |
| `keep` | 画面を押しても消さない（段 FX2b）：窓の中で段をまたいで続く演出（災害の雨）。host の中身を入れ替える・窓を閉じると消える | false |

- **待たせない**：効果は `pointer-events: none` で重ねるだけ。画面を押すと `ui` の効果はすぐ薄れて消える（出てすぐ 0.2 秒は除く）。効果のあいだ操作を止めない・効果が終わるのを待って次へ進めない。
- **チュートリアル（1 か月目）**：効果を足すのはよいが、押す場所（光るボタン・指さし・下のタブ）の上に長く残る効果は置かない。
- **演出の強さ（段 FX2）**：設定（システム → 設定）の「**演出：ふつう／控えめ／なし**」（押すたびに ふつう → 控えめ → なし。このブラウザに覚える：`localStorage` の `isl.fxLevel`。layer.ts の `fxLevel`・`setFxLevel`）。
  - ふつう：いまのまま。
  - 控えめ：**花火（`firework-burst`）・紙吹雪（`confetti`）は出さない**。光（`collect-burst`・`coin-pop` など）は 1 ドットの大きさ 3/4・光の強さ半分で小さく。
  - なし：効果の層を出さない（`playFx` が false。いま出ている効果も消す）。
  - 端末の **「動きを減らす」**（`prefers-reduced-motion: reduce`）は「なし」を初期値にする（設定で「ふつう」に戻せる）。
- （以前の決まり）「動きを減らす」のときは鳴らさない → 段 FX2 から、上の初期値「なし」で同じ扱い（`playFx` が false を返す）。音は効果の層では鳴らさない（いつもの `sfx.play` のまま。音の設定にしたがう）。
- **ゲームの数字は変えない**：効果は見た目だけ。自動プレイ（sim）からは呼ばない。
- **小さな手応えは 1 秒に 1 つ**（段 FX2）：ブランド力・エンブレム・展示・レベルアップ・外交は組 `small`（`thin: 'small'`）。続けて来たら最初の 1 つだけ（音とトーストはそのまま）。製造の火花は工房ごとの組（`craft:<uid>`）。
- **控えめ**で出さないのは `LOUD`（花火・紙吹雪・光の柱 `loot-beam`）。判定は純関数 `fxPlan(id, level)`（`tests/island-fx-layer.test.ts`）。
- **花火（`firework-burst`）は原点ではじける**（打ち上げの玉は原点の 72 ドット下から昇る）。はじける所を原点に渡す。
- **地図の点に付ける**：`main.ts` の `mapFx(id, wx, wy, o)`（ワールドの座標。縮小の全体表示・発掘のあいだは隠す）。トーストに付ける：`toastFx(e, id, o)`（トーストの絵か左の端。組 `small`）。

## 大きさ

- pixelfx の効果は「キャラクター 24 × 38 ドット」の大きさで描かれている。地図の建物（拡大率 0.5 で 100 px ほど）と並べると、**1 ドット＝1.5〜2 CSS px** がちょうどよい。
- **地図（`layer: 'map'`）**：`scale = max(1, cam.zoom × 3)`（拡大率 0.5 で 1.5 → PC は 2、スマホ 0.3 で 1）。1 倍（拡大率 0.5 で 1 ドット＝1 px）は小さすぎて読めなかった（コイン 8 px）。
- **UI の上（`layer: 'ui'`）**：PC は 2、スマホは 4/3（3 倍の画面で 4 デバイス画素）。
- 拡大は整数倍だけ（`image-rendering: pixelated`。layer.ts がデバイスの画素で丸める）。回転させない。
- 画面の外にはみ出す置き方をしない（紙吹雪の床・花火の高さを画面の中に）。

## 明るい地図の上で読めるように

pixelfx の見本は暗い背景で作られている。明るい草地（`#94b379` ほど）の上では、**加算の光は白く溶けて見えず、白いきらめきも消える**（検証で確かめた）。そこで layer.ts が：

1. **縁（ink）**：色のドットの外側に 1px のほぼ黒（`#181818`）を付ける（`docs/pixel-rules.md` の外郭線と同じ考え）。1 つだけ離れたドット（ディザで薄れていく所）には付けない（ざらつくので）。暗い幕の上で出す効果（手紙の花火）は `ink: false` でよい（軽くなる）。
2. **光を弱く**：地図は `light: 0.4`、UI は 0.7。光で明るさを出す効果（花火）は暗い所で使う。
3. キャンバスの端で切れた光を 8 px かけて弱める（四角く見えないように。pixelfx の edgeFade）。

**決まり（段 FX2）：一瞬の効果の層（`src/island/fx`）だけは半透明を許す**（光・煙・薄れて消える所・加算の光）。地図に残る絵・札・アイコン・建物は今までどおり半透明なし（`pixel:lint` の `alpha`。効果の層は `pixel:lint` の対象外のまま）。`docs/ISLAND_UX_CHARTER.md`「6. 言葉と絵」にも書いた。

## 重さの上限

- 効果ごとに小さなキャンバスを 1 枚置く（全画面のキャンバスは使わない）。動いている効果が無いときは描かない（`requestAnimationFrame` も止める）。
- 描くのは **30 コマ/秒**まで。1 コマの時間（ならした値）が 9 ms を超えたら 20、16 ms を超えたら 15 コマ/秒に自動で落とす（動きの速さは変わらない）。
- **同時に**：1 つの層に 8 つまで（超えたら古いものから消す）。重い効果（花火 240 × 248）は、スマホは 1 発ずつ（PC は 2 発まで）。
- 地図のコインは、同じお店で 0.35 秒に 1 回まで。縮小の全体表示・発掘のあいだは出さない。
- 初めて鳴らしたときの引っかかり（JS の最初のコンパイル。CPU 4 倍遅くで 1 コマ 450 ms）は、起動 3 秒後の暇な時間に各効果を数コマ回して先に済ませる（`warmFx`）。
- 新しい効果の目安：node で 1 コマ（update＋draw＋合成）**2.5 ms 以下**（pixelfx の `tools/check.mjs` も 2 ms を見る）。キャンバスは 250 × 250 ドットまで。

## 新しい効果を作るとき（pixelfx の作法）

作業はリポジトリの外（作業用の pixelfx の写し。スクリプトは `node tools/*.mjs` だけ使い、パッケージは入れない）で行い、できたファイルだけを `src/island/fx/pixelfx/fx/island/` に写す。

1. **まず既にある効果を探す**：`node tools/list.mjs <言葉>`、`docs/CATALOG.md`。候補を `node tools/render.mjs <id> --opts '{"palette":[...]}'` で描いて、contact.png を見て選ぶ。多くは `palette` を変えるだけで足りる。
2. **1 行で言う**（何が・どう動く・色・時間）。例「売上：お店の足もとに金の輪、コインが回りながら跳ね上がり、頂点できらめき、正面で白く光って小さな輪と粒にはじける。1 秒」。
3. **下書きを 2〜3 つ**（違う方向で）。`node tools/render.mjs "island/<名前>-*" --zoom 4` で全部見てから 1 つ選ぶ。
4. **見る → いちばん悪い所を直す → また描く、を 3 回以上**。`--all` で全コマ、`--gif` で動き。
5. **ゲームの背景の上で見る**：明るい草地（`#94b379`）と暗い幕の両方で、縁（ink）と光の強さを変えて比べる。
6. **`node tools/check.mjs <id>`** が通るまで直す（キャンバスからはみ出さない・最後のコマは空・乱数は seed から・重さ）。
7. 写す：`fx/island/<名前>.js` → `registry.js` と `registry.d.ts` に足す → 呼ぶ所に入れる → この文書の表に書く。

決まり：`Math.random`・`Date` を使わない（seed で決まる）。地面に付く効果は y = 0 が床。特定のゲームのキャラクター・ロゴ・画面を再現しない。

### pixelfx から効果を写すとき

- 写す前に**ファイルを全部読む**（core・効果・使う `_lib.js`）。ネットへの通信・`eval`・`Function`・外部 URL の読み込みが無いことを確かめる。
- ファイルの頭に出どころ（`// Copied from pixelfx 0.3.0 (...), MIT License, Copyright ...`）と、変えた所を書く。`NOTICE.md` に写したファイルを足す（Sprite Fusion（Hugo Duprez）由来の効果は頭にその旨が書いてあるので、そのまま残す）。
- `_lib.js` は使う関数だけを写してよい（そのときは頭に「Changed: …だけ」と書く）。
- `meta.actor` のある効果は写さない（actor を外しているため）。

### PixelLab の絵との比べ

| | pixelfx（コード） | PixelLab（絵） |
| --- | --- | --- |
| 動き | 30 コマ/秒の本当の動き（粒が飛ぶ・落ちる・光る）。1 回ずつ違う（seed） | 4〜18 コマのシート。いまの建物の完成のきらめき（`fx/sparkle_*.png`）はきれいだが毎回同じ |
| 色 | palette を渡すだけでゲームの色にそろう。あとから何度でも変えられる | 作るたびに色を指示。直すには作り直し |
| 粒の大きさ | 1 ドット＝1.5〜2 px にそろえられる。地図の絵（拡大率 0.5 で 1 ドット＝0.5 px）より粗い | 地図の絵と同じ細かさ |
| 明るい地図の上 | 光（加算）が溶けるので、縁と弱い光が要る（入れた） | 不透明の絵なので問題なし |
| 手間 | 既にある効果なら色を決めて呼ぶだけ。新しい効果は下書き → 3 回の直しで 1 時間ほど | 生成と選別・切り出し・重ね合わせの調整 |
| 向くもの | 一瞬の手応え（はじける・光る・跳ねる・花火・紙吹雪・光の柱） | 形が大事な物（建物・札・アイコン・キャラクター）、地図に残る物 |

### 災害の雨（段 FX2b）

段 FX2 では、pixelfx の `weather/storm`・`weather/rain`（320 × 180 の全画面）が重い（node で 1 コマ rain p50 3.6 ms・storm 5.3 ms。スマホ CPU 4 倍遅くで 22〜30 ms 以上の見積もり）ので見送った。段 FX2b で、**画面の一部（町の札の帯）だけに降る軽い雨**を自作した（`fx/island/rain-band.js`）。

| | 中身 |
| --- | --- |
| 効果 | 細い斜めの雨すじ（奥は暗く 4 ドット・手前は明るく 8 ドット）が帯に降り、床で 2 ドットはねる。帯の上から稲光が 1 本、2 コマ光ってもう一度ちらつく（2.6 秒のループ）。帯の端では薄れる（四角く見えないように） |

**いまの CSS との重なり**：ドット絵の雨が出たとき（`.isl-disaster.is-fxrain`）は、① ② のあいだ**全画面の CSS の雨と白い光を止め、雲と揺れは残す**（置き換え）。理由：

- 雨が 2 種類（なめらかな CSS の線とドット絵のすじ）重なると、粒の大きさがそろわず濁る。
- CSS の白い光は画面全体が 0.55 まで白くなる強い点滅で、帯の中の稲光（効果の層の一瞬の光）と二重になる。帯の稲光だけのほうが、光る所がはっきりする。
- 全画面の CSS の雨は、動く背景の模様を毎コマ描き直すので、PC（DPR 2）では効果なしの「なし」のほうがかえって重かった（下の表）。
- 雲（ぼかした楕円）と揺れはドット絵と重ならず、嵐の空気を出すので残す。③ 以降の小雨（CSS の雨 0.25）もそのまま。
