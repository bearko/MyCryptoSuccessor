# ヒーローの史実の調査（段 P の 1 段目：調査だけ）

My Crypto Successor（経営シミュレーション）で、MCH のオリジナルヒーロー 193 体それぞれを、モデルになった人物の史実・人柄に合わせて「どの部門を任せると向いているか」「どんな口調で話すか」をパーソナライズするための**下調べ**。ここではゲームのコードは書かない。結果は 1 体 1 ファイルの JSON。

## ゲームの部門（適性を評価する対象）
- `strategy` 経営企画（全社の方針・研究パネル）※基本はプレイヤー
- `logistics` 物流（調達・製造・運搬・倉庫のサプライチェーン）
- `sales` 営業（他店との交渉・販路の開拓・商圏の取り合い）
- `marketing` マーケティング（市場調査・宣伝・広報・ブランド）
- `support` カスタマーサポート（問い合わせ・満足度・炎上対応）
- `systems` システム（仕組み化・自動化・効率化）
- `rnd` R&D（発掘・研究・復刻品）
- `legal` 法務（契約・特許・争い・M&A）
- `hr` 人事（配置・採用・育成・士気）
- `general` 総務（働く環境・疲れ・設備）
- `accounting` 経理（税・決算・お金の管理）
- 役職：`sector_head` セクター長（1 つの町＝支社を丸ごと任せる）・`shop` 店長（客と対面）・`craft` 職人（工房で作る）・`buyer` 調達の買い付け・`digger` 発掘の現場

## 決まり
- 史実と伝承・創作ははっきり分ける。分からないことは推測で埋めず「不明」と書く。出典の無い断定をしない。
- 人物への敬意：中傷・差別・暴力や犯罪の美化をしない。犯罪や悲劇で知られる人物は、ゲームの中の役割を穏当に（cautions に理由）。宗教上の人物・神話の存在は信仰への配慮を。
- セリフはオリジナル（歴史上の名言を借りるなら短く・出典つき）。小説・映画・漫画・ゲームなど著作物のセリフを写さない。**商用の他社ゲームの名前やそのキャラクター設定に触れない**（調べものの中で出てきても書かない）。
- 今の企業・組織・存命の人物の実名を出さない（ヒーローのモデルになった人物の名前と、その人の時代の史実の固有名詞はよい）。
- `kind` が fictional・legendary・mythological・collaboration（例：サンタクロース、金太郎、アーサー王、ETHEREMON、サトシ・ナカモト）のときは、その元の物語・伝承・設定の要点から性格を作る（史実の欄は「伝承では…」と書く）。
- 日本語で書く。1 ファイルが壊れた JSON にならないよう、書いたら `python3 -c "import json,sys;json.load(open(sys.argv[1]))" out/<id>.json` で確かめる。
