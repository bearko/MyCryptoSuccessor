# ヒーローの史実の調査（段 P の 1 段目）

MCH のオリジナルヒーロー 193 体（vendor/mycryptoheroes の Data/Heroes/heroes.csv の category = original）について、モデルになった人物の史実・人柄・部門ごとの適性・口調とセリフの下書きを 1 体 1 ファイルでまとめたもの。段 P2（2026-11-03）からゲームで使っている：適性（部門・役職ごとの S〜D）と、口調・場面のセリフ・適性の根拠（`docs/ISLAND_PHASE1.md`「ヒーローの声と適性」）。`relations` から選んだ 30 の組み合わせは「ヒーローの組み合わせ」。能力値・スキルへの反映は後の段（段 UI6・段 I）。

- 書き方と決まり：`RESEARCH_SPEC.md`
- データ：`research/<id>.json`（193 ファイル。出典つき）
- 決定（2026-11-03）：職人（craft）の S はものを作る腕に限る（武芸の腕は別の役で活かす）
- 適性の分布（1 位の数）：経理 1・調達 2・店長 3 と少ない。ゲームでは 2 位・3 位の候補から回す前提で設計する

## ゲームへの取り込み（段 P2）

- `node scripts/heroes/build.mjs` で、ここの JSON から `src/island/p1/heroes/fit.json`（適性と best_roles・いつも読み込む）と `voice.json`（一人称・社長の呼び方・口ぐせ・場面のセリフ・適性の根拠・日本語のときだけあとから読み込む）を作る。出典・要約・関係・注意書きは入れない。**研究ファイルを直したら作り直す**（`--check` とテスト `tests/island-p1-herovoice.test.ts` が古いままだと失敗する）。
- セリフ・口ぐせは 1 行 40 字まで（超えたらビルドが止まる）。適性の根拠のうち暴力・最期にふれるもの（`build.mjs` の `WHY_NG`）は画面に出さない（「〜が、」の前まで、通らなければ札だけ）。
- レプリカ（id ＋ 10000・同じ名前）はオリジナルと同じデータを使う。
- 組み合わせ（`src/island/p1/duo.ts`・会話は `duotalk.ts`）は `relations` と史実から手で選んで書いた。会話はゲームの中の会社の仕事の場面として穏当に（各人の `cautions_ja` に従う）。
